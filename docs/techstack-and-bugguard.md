## 1.1 Principle: every dependency must earn its place

An AI builder will install 60 packages when 20 will do, and every extra one is a surface for the bugs you're seeing. The rule below is stated as a prompt instruction because that's how you enforce it:

# PART 2 — BUG GUARD

I can't debug code I haven't seen, so tell me the actual errors and I'll fix them directly. In the meantime, these are the 15 failure classes that AI builders produce in this exact application, ranked by how badly they corrupt the output. **Bugs 1–5 produce wrong numbers silently, which is far more dangerous than a crash.**

---

### BUG 1 — Floating-point drift in emissions arithmetic ⚠️ SILENT
**Symptom:** totals that don't match the sum of their parts; `1616.9999999998`; a report total differing from the dashboard by 0.01.
**Cause:** JavaScript `number` and Python `float` are binary floats. `0.1 + 0.2 !== 0.3`. Across 400 line items the drift is visible.

```typescript
// WRONG — what the builder will generate
const total = lines.reduce((s, l) => s + l.value * l.factor, 0);

// RIGHT
import Decimal from 'decimal.js';
Decimal.set({ precision: 28, rounding: Decimal.ROUND_HALF_EVEN });
const total = lines.reduce(
  (s, l) => s.plus(new Decimal(l.value).times(l.factor)),
  new Decimal(0)
);
```
```python
from decimal import Decimal, getcontext, ROUND_HALF_EVEN
getcontext().prec = 28
getcontext().rounding = ROUND_HALF_EVEN
total = sum((Decimal(str(l.value)) * Decimal(str(l.factor)) for l in lines), Decimal(0))
```
Convert to float **only at the display boundary**, never before. Postgres columns must be `NUMERIC(20,6)`.

### BUG 2 — Unit conversion off by 10³ ⚠️ SILENT
**Symptom:** a plant's diesel emissions come out as 0.12 tCO₂e or 120,000 tCO₂e.
**Cause:** the builder writes a flat conversion map and misses kL, scm, or mass↔volume.

```python
# WRONG — a lookup table with no dimensional awareness
CONVERSIONS = {"L": 1, "kL": 1000, "kg": 1}   # kg and L are not comparable!

# RIGHT — pint refuses invalid conversions instead of guessing
import pint
ureg = pint.UnitRegistry()
ureg.define("kilolitre = 1000 * litre = kL")
ureg.define("scm = metre**3")  # define your gas reference conditions explicitly

def to_canonical(value, unit, dimension, fuel_props=None):
    q = ureg.Quantity(Decimal(str(value)), unit)
    if dimension == "volume":
        return q.to("m**3")
    if dimension == "mass":
        return q.to("kg")
    if dimension == "energy":
        return q.to("MJ")
    raise UnknownDimension(unit)
```
**Mass ↔ volume for a fuel is not a unit conversion — it needs a dated, sourced density.** Never let the code do it implicitly.
**Test to add:** convert every unit in the catalogue's `allowed_units` to canonical and back; assert round-trip equality.

### BUG 3 — A missing factor silently becomes zero ⚠️ SILENT — THE WORST ONE
**Symptom:** a category shows 0 tCO₂e and everyone assumes it's genuinely zero.

```python
# WRONG — three variants the builder will produce
factor = FACTORS.get(key, 0)
factor = FACTORS.get(key) or 0
try: factor = FACTORS[key]
except KeyError: factor = 0

# RIGHT
class FactorNotFoundError(Exception): ...

def resolve(activity_key, region, year, gwp_set):
    for rule in (exact, prior_year, parent_region, global_default):
        hit = rule(activity_key, region, year)
        if hit:
            return FactorResolution(factor=hit, flags=rule.flags)
    raise FactorNotFoundError(
        f"No factor for {activity_key} / {region} / {year}. "
        f"A missing factor must never be treated as zero."
    )
```
The UI shows the row as **"Factor unavailable"** with a warning, and the report lists it in the exclusions table. Zero is a claim; unknown is a fact.

### BUG 4 — NaN propagation from an empty input ⚠️
**Symptom:** the user clears one field and the entire total renders as `NaN`.
**Cause:** `parseFloat("")` is `NaN`, and `NaN` poisons every arithmetic operation downstream.

```typescript
// WRONG
const value = parseFloat(input);
const emissions = value * factor;

// RIGHT
function parseActivityValue(raw: string): Decimal | null {
  const cleaned = raw.trim();
  if (cleaned === '') return null;              // empty is not zero
  const normalised = cleaned.replace(/[,\s]/g, '');
  if (!/^\d*\.?\d+$/.test(normalised)) return null;
  return new Decimal(normalised);
}
// Rows with a null value are EXCLUDED from the sum, not summed as zero,
// and are shown in the UI as "incomplete".
```

### BUG 5 — Stale calculation overwrites a newer one ⚠️ SILENT
**Symptom:** you type fast, then the displayed total flickers back to an older value.
**Cause:** debounced async requests resolving out of order.

```typescript
// WRONG
useEffect(() => {
  const t = setTimeout(async () => {
    const r = await fetch('/api/calculate', {...});
    setTotal(await r.json());     // an older response can land last
  }, 300);
  return () => clearTimeout(t);
}, [rows]);

// RIGHT — React Query handles ordering and cancellation
const { data } = useQuery({
  queryKey: ['calculate', inventoryId, rowsHash],
  queryFn: ({ signal }) =>
    fetch('/api/calculate', { method: 'POST', body: JSON.stringify(rows), signal })
      .then(r => r.json()),
  placeholderData: keepPreviousData,
  staleTime: 0,
});
```
Only the newest `queryKey`'s result is ever rendered; superseded requests are aborted.

### BUG 6 — `useEffect` recalculation loop
**Symptom:** the page freezes, the fan spins, "Maximum update depth exceeded".
**Cause:** an effect that recalculates on `rows` and also writes to `rows`; or an object/array dependency recreated every render.

```typescript
// WRONG
useEffect(() => { setRows(rows.map(withEmissions)); }, [rows]);

// RIGHT — derived state is computed, never stored
const rowsWithEmissions = useMemo(
  () => rows.map(withEmissions),
  [rows, factorSetVersion]
);
```
**Rule: never store a value in state that can be derived from other state.** Emissions are always derived. This single rule eliminates most React bugs in this app.

### BUG 7 — Indian number formatting rejected 🇮🇳
**Symptom:** a user types `4,50,000` (four lakh fifty thousand) and the field shows 4 or throws.
**Cause:** `parseFloat("4,50,000")` returns `4`. Western code assumes `450,000`.

```typescript
// Accept BOTH grouping conventions on input; strip all separators.
function parseIndianNumber(raw: string): Decimal | null {
  const cleaned = raw.replace(/[,\s₹]/g, '');
  if (!/^\d*\.?\d+$/.test(cleaned)) return null;
  return new Decimal(cleaned);
}

// Display in the Indian convention when locale is en-IN:
new Intl.NumberFormat('en-IN').format(450000);   // "4,50,000"
```
Also accept `"units"` as a synonym for kWh, and `Rs`/`₹`/`INR` interchangeably. This is the bug your users will hit on day one and never report — they'll just leave.

### BUG 8 — Division by zero in intensity metrics
**Symptom:** `Infinity`, `NaN`, or a crash on the results dashboard.
**Cause:** revenue, headcount or production volume is 0 or unset.

```typescript
function intensity(total: Decimal, denominator: Decimal | null) {
  if (denominator === null || denominator.isZero()) {
    return { value: null, reason: 'Denominator not provided' };
  }
  return { value: total.dividedBy(denominator), reason: null };
}
```
The UI renders "—" with a tooltip, never `Infinity`.

### BUG 9 — Scope 2 double counting ⚠️ SILENT
**Symptom:** electricity emissions are exactly double the expected value.
**Cause:** the builder sums location-based and market-based into one total.

```python
# WRONG
scope2_total = scope2_location + scope2_market

# RIGHT — two views of the same electricity
totals = {
    "scope2_location": loc,
    "scope2_market": mkt,
    "scope2_headline": loc,   # ONE of them, declared in the report

grand_total = scope1 + totals["scope2_headline"] + scope3
```

### BUG 10 — Category 3 circular recalculation
**Symptom:** infinite recursion, or Cat 3 growing on every keystroke.
**Cause:** Cat 3 is derived from Scope 1 and 2; if the builder writes it back as an `activity_record`, the next pass derives Cat 3 *from Cat 3*.

**Fix:** Category 3 is a **computed output, never a stored activity record.** Calculate it in a second pass over the immutable Scope 1/2 line results, and mark it `derived: true` so no pass ever reads it as an input.

### BUG 11 — PDF renders without the watermark, images or fonts
**Symptom:** blank logo, boxes instead of characters, no watermark on page 2+.
**Causes and fixes:**
- Remote image URL → the headless browser has no network or races the render. **Embed the logo as a base64 SVG data URI.**
- Watermark only on page 1 → `position: absolute`. **Use `position: fixed`**, which repeats on every printed page.
- Missing glyphs → fonts not embedded. **Self-host the WOFF2 and `await page.evaluate(() => document.fonts.ready)` before printing.**
- Charts blank → they render client-side after the screenshot. **Render charts to SVG server-side**, or `await page.waitForSelector('.chart-ready')`.

```python
await page.set_content(html, wait_until="networkidle")
await page.evaluate("() => document.fonts.ready")
await page.wait_for_selector(".report-ready", timeout=30000)
pdf = await page.pdf(format="A4", print_background=True,
                     margin={"top":"20mm","bottom":"22mm","left":"18mm","right":"18mm"})
```
`print_background=True` is essential — without it every background, including the watermark, is dropped.

### BUG 12 — CSV import mangles the data
**Symptom:** the first column header has an invisible `﻿`; values with commas split into extra columns; `1.2E+05` appears where a quantity should be.
**Cause:** hand-rolled `line.split(',')`, and Excel's scientific notation.

```typescript
import Papa from 'papaparse';
Papa.parse(file, {
  header: true,
  skipEmptyLines: true,
  transformHeader: h => h.replace(/^﻿/, '').trim().toLowerCase(),
  dynamicTyping: false,      // parse numbers yourself; never trust the library
});
```
Validate every row against a Zod schema, show a **preview table with per-row errors** before committing anything, and never write a partial import.

### BUG 13 — Timezone shifts the reporting period
**Symptom:** an FY ending 31 March shows as 30 March; a monthly entry lands in the wrong month.
**Cause:** `new Date("2026-03-31")` parses as UTC midnight, then renders in IST as 30 March 05:30.
**Fix:** reporting periods are **plain dates, not timestamps**. Store as `DATE` in Postgres, transport as `"YYYY-MM-DD"` strings, and never construct a `Date` object from them for display. Only genuine event timestamps use `timestamptz`.

### BUG 14 — Object mutation leaves the UI stale
**Symptom:** you edit a row, the number is right in the console but the screen doesn't update.
```typescript
// WRONG
rows[i].value = newValue; setRows(rows);          // same reference, no re-render
// RIGHT
setRows(prev => prev.map((r, idx) => idx === i ? { ...r, value: newValue } : r));
```

## PART 3 — Paste this into Antigravity to prevent the above

````
CORRECTNESS RULES — these override any other instruction. Violating one is a
bug even if the code runs.

1. ALL emissions and currency arithmetic uses Decimal (decimal.js in TS,
   decimal.Decimal in Python). Never float. Postgres columns are NUMERIC(20,6),
   never FLOAT or DOUBLE PRECISION. Convert to float only for display.
2. ALL unit conversion goes through pint (Python) with explicit dimensions.
   Never a flat lookup table. Mass<->volume for a fuel requires a dated,
   sourced density and is never implicit.
3. A missing emission factor RAISES an exception. Never `.get(key, 0)`,
   never `or 0`, never a try/except that returns 0. Zero is a claim; unknown
   is a fact and must be surfaced to the user.
4. An empty input is null, not zero. Null rows are excluded from sums and
   shown as "incomplete". NaN must never reach a total.
5. All server calls use @tanstack/react-query with an AbortSignal. Never a
   bare fetch inside useEffect with a setTimeout debounce.
6. Derived values are computed with useMemo, never stored in useState.
   Emissions are always derived from (activity, factor, gwp).
7. Number input accepts BOTH "450,000" and "4,50,000" and strips all
   separators before parsing. Display uses Intl.NumberFormat('en-IN').
   Accept "units" as a synonym for kWh.
8. Every division guards its denominator and returns null, never Infinity.
9. Scope 2 location-based and market-based are NEVER summed together. The
   grand total includes exactly one of them.
10. Scope 3 Category 3 is a computed output, never a stored activity record.
11. PDF: logo embedded as a base64 data URI, watermark uses position:fixed,
    fonts self-hosted and awaited via document.fonts.ready, charts rendered
    server-side to SVG, page.pdf called with print_background=True.
12. CSV parsing uses papaparse with dynamicTyping:false and BOM stripping.
    Validate with Zod and show a preview before committing.
13. Reporting periods are plain "YYYY-MM-DD" date strings and Postgres DATE.
    Never construct a JS Date from them.
14. Never mutate state objects or arrays. Always return new references.
15. Never remove focus outlines without a replacement. Live regions are
    debounced by at least 600ms.

DO NOT install any package outside the approved list. If you think one is
needed, stop and ask instead of installing it.

Write a unit test for every rule above before writing the feature.
````

## PART 4 — The test suite that would have caught all of this

```
tests/
  units/            round-trip every unit in the catalogue; assert invalid
                    conversions raise rather than guess
  factors/          assert a missing key raises FactorNotFoundError;
                    assert resolution flags are set on every fallback
  engine/           30 golden-path inventories with hand-verified totals;
                    assert determinism (same inputs + pins = same output);
                    assert Scope 2 is never double counted;
                    assert biogenic CO2 and Montreal gases stay out of scopes
  parsing/          "4,50,000", "450,000", "", "abc", "1.2E+05", "₹45,000"
  api/              Zod/Pydantic schema rejection of malformed records
  pdf/              render a golden report, assert page count, assert the
                    watermark element exists on every page
```

Run this in CI on every commit **and after every factor-set update**. The factor-update run is the one that catches a supplier silently changing a value.
